# v0.9 Workflow Syntax Regression Gate

Date: 2026-08-26

## Behavior

Every `.github/workflows/*.yml` and `.github/workflows/*.yaml` file must parse locally before CI runs any repository command. The gate must reject the historical v0.9 command when `--only-binary=:all:` ends an unquoted YAML scalar.

## Red evidence

Before `scripts/check_workflows.py` existed, the focused regression test failed with `ModuleNotFoundError: No module named 'check_workflows'`. This confirmed that the repository had no independent local workflow parser. A later independent review also proved that the first implementation returned no errors for empty and sequence-root workflow documents. The corrected historical mutation now produces `.github/workflows/validate.yml:20:72: invalid workflow YAML: mapping values are not allowed here`.

## Implementation

- `scripts/check_workflows.py` parses repository workflows in deterministic path order with PyYAML's safe loader, requires a nonempty mapping root, and reports stable path, line, column, and problem text.
- The command checks for PyYAML 6.0.3 before importing the parser and fails closed when the package is missing or the installed version differs.
- CI runs `python3 scripts/check_workflows.py` immediately after installing the locked validation toolchain.
- `scripts/validate_catalog.py` requires the workflow command to remain in CI.
- Unit coverage proves both current-workflow acceptance and rejection of the exact unquoted command mutation.

## Dependency evidence

- PyYAML 6.0.3 and types-PyYAML 6.0.12.20260815 have exact versions, reviewed source and license records, and SHA-256 wheel hashes.
- A CPython 3.12 manylinux x86-64 `pip download` with `--require-hashes` resolved and verified all eight locked CI wheels.
- PyYAML and types-PyYAML declare no transitive package dependencies. Absence of a known advisory is not claimed as proof of safety.
